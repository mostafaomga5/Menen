# ملاحظات الجدوى: محرر ميكانيكي 3D على الويب

## تحرير المجسم مباشرة

يوفر Three.js `TransformControls` أداة تحريك ودوران وتغيير مقياس على محاور X/Y/Z، مع اختيار المحور المحلي أو العالمي وخصائص snap. توثيق الفئة يذكر أحداث مؤشر/لمس. هذا يسمح ببناء gizmo مباشر، لكنه لا يضيف نظام CAD أو قيود تجميع أو حفظ مشروع بمفرده؛ تلك مسؤولية التطبيق. يجب اختبار الدقة واللمس على هاتف فعلي، لأن مساحة الإصبع قد تتطلب أهدافًا أكبر أو حقولًا رقمية بديلة. [1]

تدعم `OrbitControls` بحسب توثيق Three.js التدوير بإصبع واحد، والتقريب/الإبعاد والتحريك بإصبعين. هذا أساس مناسب لتدوير مجسم الماكينة على الشاشة اللمسية. [2]

## الفيزياء والتصادمات

Rapier متاح كحزمة JavaScript ثلاثية الأبعاد، ويهيئ WebAssembly بشكل غير متزامن. يمكن استخدامه مع bundler مثل Vite، وتوجد حزمة توافق تدمج ملف WASM عند الحاجة. Rapier يوفر أجسامًا صلبة ومصادمات، وأشكالًا أولية ومركبة وشبكية. ويدعم مفاصل ثابتة ومحورية منزلقـة ودورانية، وحدودًا للمفصل المنزلق ومحركات joint؛ ويقدم كشف التلامس وأحداث التصادم وقوى التلامس وCCD لبعض حالات الحركة السريعة. هذا يجعله خيارًا تقنيًا معقولًا لكشف الاصطدامات والحركة على مفاصل محددة، شريطة تعريف collider لكل جزء وبياناته واختبار معدل الخطوة والأداء. [3][4][5]

هذه الميزات لا تجعل الموقع «محاكاة حقيقية 100%». ملف الويب لا يحتوي تلقائيًا بيانات CAD أو كتل أو مراكز كتلة أو احتكاك أو معاملات صمامات وتدفق هواء. ولا يثبت محرك التصادم وحده القوة أو التشوه أو الإجهاد أو أداء الغراء. النموذج الفيزيائي يجب أن يعلن فرضياته، ويعرض توقفًا عند القيود التي نمذجناها فقط. القطع غير المدعومة أو ذات collider تقريبي قد تعطي نتائج غير مطابقة للقطعة الفعلية.

## عرض أفقي للهاتف

تتيح Screen Orientation API طلب `lock('landscape')` في البيئات التي تدعمه، لكنه غير متاح في بعض المتصفحات، ويعمل عادة على الهاتف وفي سياق fullscreen، وقد يرفض المتصفح الطلب لأسباب دعم أو صلاحيات. لذلك التنفيذ الصحيح هو شاشة تطلب من المستخدم تدوير الهاتف، مع محاولة قفل الاتجاه اختياريًا بعد تفاعل المستخدم أو fullscreen، واستمرار الواجهة برسالة/بديل إذا رُفض الطلب. لا يمكن ضمان فرض تدوير النظام من صفحة ويب عادية. [6]
